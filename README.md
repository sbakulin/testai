# Платежи

Сервис пополнения счетов клиентов через платёжного провайдера MockPay.

- Клиент пополняет счёт: сервис создаёт платёж в MockPay, провайдер присылает вебхук об оплате, сервис зачисляет деньги в журнал проводок.
- После зачисления клиенту отправляется чек через сервис чеков.
- Возвраты оформляет оператор поддержки: сервис создаёт возврат в MockPay, результат приходит вебхуком, списание попадает в журнал.
- Кабинет оператора — веб-интерфейс для поддержки: список счетов, платежи счёта с поиском, карточка платежа и оформление возврата.

Описание API провайдера — в [PROVIDER.md](PROVIDER.md).

## Требования

- Node.js 22.13 или новее (версия для `nvm` указана в `.nvmrc`: `nvm use`)
- git

## Запуск

```sh
npm install
npm run connect -- КОД   # подключиться к стенду: код выдаётся вместе с доступом
npm run dev              # API, кабинет оператора и слушатель вебхуков
npm test                 # тесты API, кабинета и скриптов
```

- Кабинет оператора: http://localhost:5173
- API: http://localhost:3000

`npm run connect` пишет `.env.local` (адрес стенда, код, секрет вебхуков), загружает исходные данные в локальную базу и кладёт рабочие материалы в `task/`. Если `npm run dev` уже запущен, после подключения его нужно перезапустить.

Прочие команды:

- `npm run reset` — вернуть локальную базу к исходным данным из `task/seed.json`.
- `npm run submit` — собрать изменения и отправить их на стенд (перед отправкой показывает состав архива и спрашивает подтверждение).
- `npm run listen` — только слушатель вебхуков (входит в `npm run dev`).
- `npm run dev -w api`, `npm run dev -w web` — API или кабинет по отдельности.

## Как приходят вебхуки

Локальный сервис не виден из интернета, поэтому вебхуки MockPay забирает слушатель (`scripts/listen.mjs`): он опрашивает стенд и пересылает каждую доставку в `POST http://127.0.0.1:3000/webhooks/mockpay`, а код ответа сообщает обратно провайдеру. В консоли слушателя видна каждая попытка доставки и её результат.

## Структура

```
api/                  сервис на Fastify, база — node:sqlite (api/data/app.db)
  src/app.ts          сборка приложения и обработка ошибок
  src/routes/         счета, платежи, возвраты, вебхуки MockPay
  src/ledger.ts       журнал проводок и остатки
  src/mockpay.ts      клиент MockPay
  src/receipts.ts     клиент сервиса чеков
  src/money.ts        перевод сумм между тийинами и строками провайдера
  src/schema.sql      схема базы
  test/               тесты API (node:test)
web/                  кабинет оператора на React + Vite
  src/pages/          страницы: список счетов, счёт
  src/components/     таблица платежей, карточка платежа, форма возврата
  src/lib/            клиент API, хуки, форматирование
scripts/              connect, listen, reset, submit и их тесты
```

## Деньги

Все суммы внутри сервиса — целые числа в тийинах (1 сум = 100 тийинов), поля с суффиксом `_minor`. MockPay принимает и присылает суммы строкой в сумах с двумя знаками после точки (`"150000.00"`); перевод — в `api/src/money.ts`, без чисел с плавающей точкой. Остаток счёта хранится в `ledger_balances` и меняется только проводками из `ledger_postings`.

## Примеры запросов

```sh
# создать счёт
curl -s -X POST http://localhost:3000/accounts \
  -H 'content-type: application/json' -d '{"owner_name":"ООО Ромашка"}'

# создать платёж на 1 500,00 сум
curl -s -X POST http://localhost:3000/payments \
  -H 'content-type: application/json' -d '{"account_id":"acc_…","amount_minor":150000}'

# остаток счёта
curl -s http://localhost:3000/accounts/acc_…/balance

# платежи счёта, поиск по номеру
curl -s 'http://localhost:3000/accounts/acc_…/payments?q=pay_'

# платёж с возвратами
curl -s http://localhost:3000/payments/pay_…

# возврат 500,00 сум по оплаченному платежу
curl -s -X POST http://localhost:3000/payments/pay_…/refunds \
  -H 'content-type: application/json' -d '{"amount_minor":50000}'
```

## Тесты

`npm test` в корне запускает тесты API, кабинета (Vitest + Testing Library) и скриптов. Тесты лежат рядом с кодом: `api/test/`, `web/src/**/*.test.tsx`, `scripts/test/`.

`data-testid` используются автотестами команды — не переименовывайте.
